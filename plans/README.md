## Findings considered and rejected

- Having the component start/manage branch dev servers itself: rejected — the
  component is a vendored, self-contained React component (peer deps only,
  repo `CLAUDE.md`); provisioning preview servers is consuming-app
  infrastructure. Plan 001 exposes `resolvePreviewUrl(branchName)` instead.
- Static source scanning of app code as the "auto-detect" mechanism for plan
  002: rejected — apps under test run on another machine, may be minified
  builds, and traffic observation captures real request/response shapes that
  source scanning cannot. Plan 002 detects endpoints from live traffic.
- Agent-injection HTML rewriting inside the plan-002 mock proxy: deferred —
  the proxy fronts the apps' API, not their pages; see plan 002 maintenance
  notes.
- Injecting a `listBranches` callback instead of fetching from GitHub in the
  component: rejected in the 2026-08-18 run — superseded: the ADR-0002
  migration adopted the `listBranches` callback after all (GitHub-shaped
  fetch now lives in `app/src/App.jsx`; component is GitHub-agnostic). Plan
  003 builds on that contract.
- Re-migrating the app to a different framework (requested 2026-08-19):
  rejected — already done; ADR-0002 (accepted 2026-08-18) chose Vite + React
  and explicitly rejected Next.js (no SSR benefit, complicates multi-origin
  dev); migration landed in `790bab6`. Re-open the ADR only with a new
  reason, not via a plan.
- Putting the repo picker inside the vendored component (a `listRepos`
  contract): rejected — grows the vendored surface and pushes repo/GitHub
  concerns into a deliberately GitHub-agnostic component; operator chose the
  app-shell picker (plan 003).
- Preconfigured-repo-list-only chooser (no free-text entry): rejected in
  favor of app-shell free entry; the preview-URL mapping constraint is
  handled by `VITE_PREVIEW_URL_TEMPLATE` plus an inline resolve error for
  unmapped repos (plan 003).
